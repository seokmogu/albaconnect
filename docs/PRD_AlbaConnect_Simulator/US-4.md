# US-4: 사용자는 본인 컨텍스트를 고정하기 위해 ID 기반 진입점을 선택할 수 있다

**Epic**: Epic 1 - 마이페이지

**Phase**: Phase 1

**Priority**: P0

**구현 상태**: 미구현 (`/sim/me`)

---

## 배경 및 해결하고자 하는 문제

마이페이지(US-1, US-2)는 본인 시점으로 고정된 화면이다. 그런데 시뮬레이터에는 실제 로그인 시스템이 없다. 사용자가 "나는 누구인가"를 정하는 진입점이 없으면 마이페이지를 사용할 수 없다.

실제 서비스라면 로그인이 이 역할을 하지만, 시뮬 환경에서는 312개 사업장·9,950명 워커 중 하나를 본인으로 선택하는 가벼운 진입점이 필요하다. 이 진입점은 인증을 흉내 내지 않고, 단지 컨텍스트를 고정하는 역할만 한다.

이 스토리는 사용자가 역할(구인자/구직자)과 ID를 선택해 본인 컨텍스트를 고정하는 진입 화면을 정의한다.

---

## 기능 요구사항 (Functional Requirements)

### 세부 기능

**1. 역할 선택**
진입 화면에서 구인자 또는 구직자 역할을 선택한다.

**2. ID 선택/입력**
선택한 역할에 해당하는 ID를 목록에서 고르거나 직접 입력한다. 구직자는 9,950명 규모이므로 검색·페이지네이션을 제공한다.

**3. 마이페이지 이동**
선택 완료 시 해당 역할·ID의 마이페이지로 이동한다.

**4. 컨텍스트 표시**
마이페이지 상단에 현재 고정된 본인 역할·ID·이름을 표시해, 사용자가 누구 시점인지 항상 인지하게 한다.

---

## 상세 시나리오 (Detailed Scenarios)

### 시나리오 1: 정상 플로우 (Happy Path)

1. 사용자가 진입 화면에서 "구인자"를 선택한다.
2. 사업장 목록(또는 검색)에서 본인 사업장을 고른다.
3. 구인자 마이페이지로 이동하고 상단에 본인 매장명이 표시된다.

### 시나리오 2: 대체 플로우 (Alternative Flows)

* 구직자 선택: 워커 목록에서 카테고리 필터·페이지네이션으로 ID를 찾는다.
* ID 직접 입력: `emp-001`, `w-0001` 형식 ID를 직접 입력해 바로 진입한다.

### 시나리오 3: 에러 처리 (Error Handling)

* 존재하지 않는 ID 입력: "해당 ID를 찾을 수 없습니다" 안내, 진입 차단.
* 역할과 ID 형식 불일치(구인자 역할에 `w-` ID): 형식 안내.

### 시나리오 4: 엣지 케이스 (Edge Cases)

* 컨텍스트 미선택 상태로 마이페이지 URL 직접 접근: ID가 URL에 있으면 그대로 진입, 없으면 진입 화면으로 유도한다.

---

## Business Rules

* **정책**: 진입점은 인증이 아니라 컨텍스트 고정 용도다. 비밀번호·세션을 요구하지 않는다.
* **검증**: 선택/입력 ID가 실재하는지, 역할과 ID 형식이 일치하는지 확인한다.
* **UX 보호**: 마이페이지 상단에 항상 본인 컨텍스트를 표시해 혼동을 막는다.
* **엣지 케이스**: URL에 ID가 포함되면 진입 화면을 거치지 않아도 된다.

---

## Acceptance Criteria

- [ ] 진입 화면에서 구인자/구직자 역할을 선택할 수 있다
- [ ] 역할에 맞는 ID를 목록·검색·직접 입력으로 선택할 수 있다
- [ ] 선택 완료 시 해당 마이페이지로 이동한다
- [ ] 마이페이지 상단에 본인 역할·ID·이름이 표시된다
- [ ] 존재하지 않는 ID·형식 불일치는 안내 후 진입이 차단된다
- [ ] URL에 ID가 포함된 경우 진입 화면 없이 바로 진입한다

---

## 성공 지표 (Success Metrics)

* ID 선택 → 마이페이지 진입 성공률 100%
* 잘못된 ID 차단율 100%
* 진입 화면 → 마이페이지 이동 1초 이내

* **제약**: 시뮬 환경이므로 실제 인증·세션을 구현하지 않는다
